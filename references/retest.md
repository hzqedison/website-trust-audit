# 按指定范围复测或对比

仅复测用户指定的网站、时间窗口、地区、登录状态、设备、页面和检查层级。开始前把范围写清；无法完成的部分显式写 `blocked` 或 `not_tested`，不以 HTTP 成功代替视觉/安装/支付检查。

对每个主张保存可复核证据：来源 URL 或项目内相对路径、观察时间（含时区）、方法、站点/语言/页面/设备 scope，以及 HTML、截图或摘录等附件。附件只证明留存了材料；结构验证器不核实附件语义真伪。页面当前观察只表示本次上下文中的复核，不证明官网说法真实。

新旧对比必须保留历史记录，不覆盖旧值。逐项标记新增、变更、撤回、未复核及原因；确保时间、地区、设备、页面版本、登录态、统计口径可比。两个不同的下界数字不自动矛盾。没有可比条件时报告差异，不强造趋势。

先列出预期覆盖单元及语言入口来源，再逐格采集。动态页面需区分 HTTP、DOM 与可见渲染结果；资费条款记录地区、登录态、PC/移动端及活动时间。若无法证明语言入口完整，分母应标为未知，不报告 100% 覆盖。以站点 × 语言 × 页面 × 设备 × 检查层级建立覆盖矩阵；可另含 `check`。`verified` 必须引用 scope 一致的当前证据，且每条引用只能是 observation、official_claim 或 third_party；user_requirement 或 reviewer_inference 不能单独证明页面检查已执行。复核者还要确认方法确实覆盖该检查项。未知/阻塞不能计为失败或零分。输出范围外事项，不扩展为改版建议或排名，除非用户明确提出。

只有用户要求评分时，才可采用十维候选 rubric：价值表达、主体、 安全与隐私透明度、评价、效果证据、下载路径、试用与付费、信息层级、跨设备、本地化。需解释 0/5/10 锚点及每维证据；缺证标 `N/A`，不当作 0，也不跨不同覆盖硬排名。维度权重属于显式评审约定，不代表用户批准。

完成后按 `references/evidence-schema.md` 保存 JSON 包并运行验证脚本。合法缺口可通过结构检查；报告中仍须说明覆盖数量不代表审计完成。验证器不联网、不获取网页、不运行下载或安装软件、不支付。复核者还须人工确认被引用证据的 `method` 确实覆盖该行的 `check` 层级；结构上的站点/语言/页面/设备匹配并不能证明方法匹配或语义成立。
