# 整理信息基线

此模式用于把现有资料整理成带时间与证据状态的基线，不进行网站改版决策、优先级裁决或默认排名。

## 记录

每条记录使用唯一 ID、表述、证据类型（`observation`、`official_claim`、`third_party`、`reviewer_inference`、`user_requirement`）、状态（`historical`、`current`、`unverified`）、来源、观察时间、站点/语言/页面/设备范围、方法和证据文件。保留原始话语与评审解释的边界。链接存在不等于当前事实；引用旧记录时仍标 `historical`。

区分官网自述、第三方评价、直接观察、推断和用户明确要求。官网 Logo、认证标识、伙伴页或隐私披露不能单独证明商业合作、软件安全、安装包行为或 PC 客户端实际收集。不同数字下界可能同时成立；需先核对对象、时间和统计口径。未映射到明确问题的数字回答不能被改写成用户需求。历史资料只有日期时保留 `YYYY-MM-DD` 精度；观察时间未知时记 null 并用 `time_note` 说明，不补造午夜或时区。

## 观测边界

HTTP 响应不等于页面视觉、安装流程或母语审校。方向属性 `dir` 缺失、HTML 中残留文案、动画初始值为 0 都需要在渲染后的页面中验证，不能直接定性。下载、安装、运行、支付各为独立检查层；未做的标记 `not_tested` 或 `blocked`，不可填 0 分。

语言覆盖按站点 × 语言 × 页面 × 设备 × 检查层级逐格列出，状态为已验证、部分、阻塞、未测试，并解释缺口。不要用入口数量替代全语言体验覆盖。

第三方评价要保留样本数、采集时间、邀请方式或可知的样本来源；样本评价不能代表总体或性能因果。只有用户要求评分时才评分：先说明 rubric、各项证据和覆盖率；证据不足则不排序。

建议输出基线摘要、范围/方法、证据账本、逐格覆盖、未决问题和限制。把建议与已确认需求分开。没有明确用户需求映射的建议必须标为候选，而非要求。
